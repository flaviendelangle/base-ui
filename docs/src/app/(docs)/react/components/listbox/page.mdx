## Usage guidelines

- **Always visible**: Unlike [Select](https://base-ui.com/react/components/select), the Listbox is always open and does not use a popup or trigger. Use it when all options should be visible at once.
- **Multi-select support**: Set `selectionMode="multiple"` or `"explicit-multiple"` to allow selecting more than one item.
- **Form controls must have an accessible name**: Prefer `<Listbox.Label>`, or provide an `aria-label` on `<Listbox.List>` when no visible label is rendered. See the [forms guide](https://base-ui.com/react/handbook/forms).

## Anatomy

Import the component and assemble its parts:

```jsx title="Anatomy"
import { Listbox } from '@base-ui/react/listbox';

<Listbox.Root>
  <Listbox.Label />
  <Listbox.SortableProvider>
    <Listbox.List>
      <Listbox.Item>
        <Listbox.ItemIndicator />
        <Listbox.ItemText />
        <Listbox.SortHandle />
        <Listbox.SortPreview />
      </Listbox.Item>
      <Listbox.Group>
        <Listbox.GroupLabel />
      </Listbox.Group>
      <Listbox.LoadingTrigger />
    </Listbox.List>
  </Listbox.SortableProvider>
</Listbox.Root>;
```

## Examples

### Selection modes

The `selectionMode` prop controls how items are selected:

- `"single"` (default): clicking an item selects it and deselects any other.
- `"multiple"`: every click toggles an item. Hold <kbd>Shift</kbd> and click to select a contiguous range.
- `"explicit-multiple"`: clicking an item replaces the selection. Hold <kbd>Ctrl</kbd>/<kbd>⌘</kbd> and click to toggle, or <kbd>Shift</kbd> and click to select a range.

### Sorting

Wrap the list in `Listbox.KeyboardSortableProvider` to enable keyboard sorting. Pass `onItemsReorder` and render the values in the proposed order.
Focus an item and press <kbd>Alt</kbd> + <kbd>ArrowUp</kbd> or <kbd>Alt</kbd> + <kbd>ArrowDown</kbd> to move it. Horizontal lists use <kbd>Alt</kbd> + <kbd>ArrowLeft</kbd> and <kbd>Alt</kbd> + <kbd>ArrowRight</kbd>, respecting the text direction.

Completed keyboard moves and final pointer outcomes are announced politely. Live pointer sorting does not announce intermediate positions. Use `getAnnouncement` on either provider to customize the text. It receives `items` with their current values and positions, `destination`, `reason` (`'keyboard'` or `'drag'`), and `outcome` (`'moved'`, `'unchanged'`, or `'canceled'`). The destination describes the first moved item's resulting group and flat list index after the operation, or is `null` if no moved items remain. Return an empty string to suppress a message.

Sorting a selected item moves the selected items together in list order. Disabled items stay in place. Selection continues to work with <kbd>Enter</kbd> and <kbd>Space</kbd>.

Use `isItemSortingDisabled` on either provider to exclude an item from sorting while keeping it selectable and available as a destination.

### Live sorting

Set `reorderOn="move"` to update the order while dragging. Render each proposed order from `onItemsReorder`. Canceling the drag or dropping outside the list restores the original order. Items added during the drag stay in their current group and slot within that group. If that slot no longer exists after restoration, the item goes at the end. Item edits are kept, and deleted items are not restored.

### Moving between groups

Give each `Listbox.Group` a stable `id` when your application allows items to move between groups.
`onItemsReorder` provides the complete proposed order as `details.order`, with each item's value and group ID. Apply that metadata to update both the order and group membership. It also contains the original groups when a live move is canceled.

```tsx
<Listbox.SortableProvider
  onItemsReorder={(_, details) => {
    setItems(details.order.map(({ value, groupId }) => ({ value, groupId })));
  }}
>
  {/* Render each item under the Group whose id matches its groupId. */}
</Listbox.SortableProvider>
```

### Drop positions

By default, the first half of a row inserts before it, and the second half inserts after it. Horizontal lists use the corresponding left and right halves.
Use `getDropPosition` to change these zones. It receives the application value as `item`, sorting metadata as `itemMetadata`, the drag source as `source`, and normalized pointer coordinates. `source` is a `Draggable.DragSource`, matching external-drop callbacks; read dragged items from `source.payload.items`. Return `'before'`, `'after'`, a position object, or `null` to reject that position.

`groupId` is `null` for ungrouped items. Item and destination indices are zero-based and span the entire list, including all groups. They do not reset at group boundaries. Destination insertion indices refer to the order before removing the moved items.

Tree uses indices within the current or destination parent. Listbox retains list-wide indices, including all groups.

Use `onDropPositionChange` for a custom placement indicator. Items also expose `data-drop-position="before"` or `data-drop-position="after"`.

Use `data-moving` to style all items participating in the active pointer sort. The equivalent render state is `moving`. Selected items disabled for sorting are excluded. This state clears when the gesture ends or is canceled. The drag engine's `data-dragging` remains limited to the item physically picked up.

### Preview and drag options

The preview callback receives item values captured at pickup. Later value replacements do not change that data; values are not deep-cloned.

The default preview clones the dragged row. Render `Listbox.SortPreview` inside an item to customize it, show a selected-item count, or hide it with `disabled`:

```tsx
<Listbox.Item value={item}>
  <Listbox.ItemText>{item.label}</Listbox.ItemText>
  <Listbox.SortPreview>
    {({ items }) => <span>{items.length} selected items</span>}
  </Listbox.SortPreview>
</Listbox.Item>
```

Pass `draggableProps` to `Listbox.Item` to configure activation, modifiers, or drag event handlers on its existing `Draggable.Root`. You can customize one drag option while keeping managed sorting.

### Drag and drop outside the list

For interactions with elements outside the Listbox, use the [Draggable utility](/react/utils/draggable).
Pass a shared `kind` to `Listbox.SortableProvider` and the external target. `getDragPayload` supplies application data in the payload's `data` field. The payload also contains `id`, `itemIds`, pickup snapshots in `items`, and an opaque `collectionId` identifying the source collection, matching Tree sorting payloads.
The external target handles the transfer and updates the affected collections. Listbox sorting only reorders items within its own list.

To accept incoming drags on individual options, use `Listbox.ItemExternalDropTarget` in place of `Listbox.Item`. It retains selection, focus, and keyboard behavior and works with or without `Listbox.SortableProvider`.

```tsx
<Listbox.ItemExternalDropTarget
  value={item}
  accept={fileKind}
  canDrop={({ source, destination }) => canImport(source.payload, destination)}
  onDraggableDrop={({ source, destination }) => transferFiles(source.payload, destination)}
>
  <Listbox.ItemText>{item.label}</Listbox.ItemText>
  <Listbox.ItemIndicator />
</Listbox.ItemExternalDropTarget>
```

Same-list drags remain owned by sorting, even when sorting rejects the move. External drags use the explicit target behavior. Each option has one drop-target registration. Set `dropDisabled` to disable external acceptance without disabling selection or sorting.

The default placement is before or after the option, respecting horizontal orientation and text direction. `getDropPosition` can override placement; returning `null` rejects the drop. `canDrop` validates the resolved destination; returning `false` rejects the drop, including ancestor targets. Unmatched kinds can fall through to an ancestor target.

The destination contains `groupId` and a zero-based `index` across the entire list, including all groups. It is not an index within the group. Tree's destination index is relative to the destination parent. `onDrop` retains its native HTML drag-and-drop meaning. `onDraggableDrop` handles the application transfer and does not automatically mutate either collection. For controlled collections, confirm the destination update before deleting source items.

External placement uses the existing `dragOver` and `dropPosition` item states. `onDropPositionChange` receives `null` when placement clears.
